# 语言对齐测试报告：中文 vs 英文向量检索

**报告日期**: 2025-12-15

---

## 测试目标

验证假设：**英文问题 + 英文表描述 + 英文嵌入模型**是否能提升向量检索的召回率。

---

## 测试配置

| 配置项 | 方案 A（中文） | 方案 B（英文） |
|--------|---------------|---------------|
| 问题语言 | 中文原文 | LLM 翻译成英文 |
| 表描述语言 | 中文 | LLM 翻译成英文 |
| 嵌入模型 | bge-large-en-v1.5 | bge-large-en-v1.5 |
| 索引表数 | 344 | 344 |

---

## 测试结果

| 问题 | 期望表 | 中文召回率 | 英文召回率 |
|------|--------|-----------|-----------|
| ciscoA 告警统计 | `event_history`, `t_bz_config_ci_ne_root` | 0% | 0% |

**汇总**:

- 英文方案平均召回率: **0%**
- 提升: **0 个百分点**

---

## 结果分析

### 为什么英文方案也失败了？

检查 LLM 检索到的表：

| 期望表 | 实际检索到（英文方案） |
|--------|----------------------|
| `t_bz_config_ci_ne_root` | `sdw_dp_device`, `t_gn_all_net_device` |
| `event_history` | `t_bz_sdn_alarm`, `event_history_sdwan` |
| `t_bz_config_customer` | `customer`, `customer_svr_pkg_limit` |

**问题**：核心表的描述与实际语义不匹配。

### 查看核心表的英文描述

```
t_bz_config_ci_ne_root:
英文描述: "Stores root network element configuration for customers, including device ID, IP, model, and status..."

问题: "How many devices are currently on the platform?"
检索到: sdw_dp_device, t_gn_all_net_device（语义更直接匹配 "device"）
```

**根因**：嵌入模型选择的是与问题词汇最接近的表，而不是业务逻辑上最相关的表。

---

## 核心发现

1. **语言对齐不是主要问题**
   - 无论中文还是英文，核心表都没有被检索到
   - 问题不在于语言，而在于**表描述的语义表达**

2. **表名影响很大**
   - `sdw_dp_device` 包含 "device" 词根，容易被匹配
   - `t_bz_config_ci_ne_root` 表名没有明显的业务含义

3. **向量检索的本质限制**
   - 向量检索基于词汇/语义相似度
   - 业务上最重要的表 ≠ 语义上最相似的表

---

## 结论

> [!CAUTION]
> **单纯的语言翻译无法解决向量检索的召回问题。**
> **问题的根源是：核心业务表的描述没有包含用户查询中的关键词。**

**向量检索方案的结构性问题**：
- 依赖词汇匹配，而非业务理解
- 表名/描述的措辞直接影响召回
- 需要人工确保关键词出现在核心表描述中

---

## 可选的后续方向

1. **放弃向量检索**：使用 LLM 直接选表（之前测试召回率 21.4%）
2. **混合方案**：向量检索 + 关键词匹配 + 核心表白名单
3. **改进表描述**：在核心表描述中显式加入常见查询词（如"设备主表"、"告警历史"）

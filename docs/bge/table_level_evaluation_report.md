## 三、失败原因分析

### 3.1 召回失败的核心问题

**问题：表描述缺乏跨表关联语义**

| 表 | 描述问题 | 影响 |
|---|--------|-----|
| `t_bz_config_ci_ne_root` | 无"告警"关键词 | 告警查询无法匹配 |
| `event_history` | 未被召回 | 告警分析失败 |
| `t_bz_config_customer` | 未被召回 | 客户关联失败 |

**原因**：
- LLM 生成描述只能根据列名推断，无法知道表间隐含关联
- 用户问"设备ciscoA告警"→ `ciscoA` 是数据值，不在 embedding_text 中
- 设备表描述没有"告警"词，无法被告警相关查询召回

### 3.2 SQL 生成问题

即使表被召回，LLM 仍选择错误的表生成 SQL：

| 测试 | 正确表 | LLM 选择的表 |
|-----|-------|-------------|
| 3 | `t_bz_config_customer` | `customer` |
| 4 | `t_bz_config_ci_ne_root` | `sdw_dp_device` |
| 5 | `t_bz_config_ci_ne_root` | `report_new_dev` |
| 6 | `t_bz_config_ci_ne_root` | `uptime` |

## 四、表级别方案局限性

| 局限性 | 说明 |
|-------|-----|
| **1. 无法匹配数据值** | ciscoA、客户名等具体值不在描述中 |
| **2. 表间关联不明确** | 设备表与事件表的 NE_ID 关联难以体现 |
| **3. 语义稀释** | 一个表 50+ 列，核心语义被稀释 |
| **4. 相似表混淆** | `customer` vs `t_bz_config_customer` |

## 五、后续方向建议

### 方案 A：优化表级别（短期）

| 优化项 | 预期效果 |
|-------|---------|
| 查询重写 | 将"ciscoA"→"设备主表某设备" |
| 核心表白名单 | 强制包含核心表 |
| 手动补充关联 | 在描述中加入表间关系 |

### 方案 B：列级别检索（中期）

| 优势 | 说明 |
|-----|-----|
| **更精确的语义匹配** | 列描述更聚焦 |
| **Max Score 聚合** | 列→表的精确映射 |
| **列可能包含值暗示** | 如"设备名称"暗示ciscoA |

**流程**:
```
用户问题 → 列检索 → Max Score → 表选择 → Schema 加载 → SQL 生成
```

### 方案 C：两阶段混合（长期）

1. **粗召回**：表级别检索，Top 20
2. **精排序**：列级别重排，返回 Top 5

---

## 六、结论

**当前表级别方案效果有限**（召回率 74%，SQL 评分 51/100）。

**主要问题**：
1. 表描述无法体现数据值（如 ciscoA）
2. 表间关联语义缺失
3. LLM 在相似表中选择错误

**建议**：探索列级别检索或两阶段混合方案。

# BGE-M3 检索模式对比报告

**日期**: 2025-12-16

---

## 测试结果对比

| 指标 | Dense-only | Hybrid (Dense 0.7 + Sparse 0.3) |
|------|-----------|--------------------------------|
| **表完全召回** | 4/7 (57%) | 4/7 (57%) |
| **平均表召回率** | 74% | 74% |
| **平均 SQL 评分** | 54/100 | 53/100 |
| **优秀(≥80分)** | 0/7 (0%) | 0/7 (0%) |

> **结论**：混合检索在当前配置下**没有带来显著提升**。

## 关键发现

### 1. Sparse 向量对排名的影响

| 测试 | 表 | Dense 分数 | Sparse 分数 | Hybrid 分数 | 排名变化 |
|-----|---|-----------|------------|-------------|---------|
| 4 | `t_bz_config_ci_ne_root` | 0.5400 | 0.1289 | 0.4167 | **#2 → #1** |
| 5 | `t_bz_config_ci_ne_root` | 0.4746 | 0.1039 | 0.3634 | **#3 → #1** |
| 6 | `t_bz_config_ci_ne_root` | 0.4878 | 0.0958 | 0.3702 | #2 → #2 |

**分析**：Sparse 向量在某些情况下能帮助核心表提升排名，但效果有限。

### 2. 为什么混合检索没有显著提升？

1. **表描述缺乏关键词**：
   - `t_bz_config_ci_ne_root` 的描述中缺少"告警"、"alarm"等词
   - 导致 Sparse 向量无法匹配问题中的关键词

2. **Sparse 分数普遍较低**：
   - 大多数表的 Sparse 分数在 0.05-0.20 之间
   - 对 Hybrid 分数的贡献有限

3. **根本问题仍是表描述质量**：
   - 无论用 Dense 还是 Hybrid，核心表描述不包含关联语义时都无法被召回

## 建议

### 短期优化（推荐）

| 优化项 | 预期效果 |
|-------|---------|
| **增强表描述**：在核心表中加入关联语义 | 召回率 74% → 90%+ |
| **测试更高 Sparse 权重**：如 Dense:Sparse = 0.5:0.5 | 可能提升关键词匹配 |

### 长期优化

| 优化项 | 预期效果 |
|-------|---------|
| 使用 ColBERT 检索 | 更精确的 token 级别匹配 |
| 实体识别 + 多路召回 | 针对不同实体类型分别检索 |

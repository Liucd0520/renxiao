> **技术组 → 业务组**

## 背景说明

我们正在开发 Text-to-SQL 系统，让用户可以用自然语言查询数据库。目前技术侧的检索召回率已达到 **95.7%**，但需要业务侧的支持来进一步验证和优化。

**当前瓶颈**：真实标注数据太少（仅 7 条），无法进行充分的模型评估和优化。

---

## 一、核心需求：真实标注数据（最重要）

### 需求数量
- **最少 50 条**，越多越好
- 建议按难度分布：Simple 20 条 / Medium 20 条 / Hard 10 条

### 每条数据需要包含

| 字段 | 必填 | 说明 | 示例 |
|-----|:---:|------|------|
| **自然语言问题** | ✅ | 业务人员日常会问的问题 | "查询上周告警数量最多的前10个设备" |
| **正确 SQL** | ✅ | 能在数据库跑通的 SQL | `SELECT device_id, COUNT(*) FROM event_history WHERE event_time >= '2025-01-01' GROUP BY device_id ORDER BY COUNT(*) DESC LIMIT 10` |
| **涉及的表** | ✅ | 这条 SQL 用到了哪些表 | `event_history, t_bz_config_ci_ne_root` |
| **难度** | 可选 | Simple / Medium / Hard | Medium |
| **业务场景** | 可选 | 这个问题属于什么业务场景 | 告警统计 |

### 数据格式建议

可以用 Excel 或 CSV 提供，格式如下：

| 问题 | SQL | 涉及的表 | 难度 |
|-----|-----|---------|-----|
| 查询上周告警数量最多的前10个设备 | SELECT ... | event_history, t_bz_config_ci_ne_root | Medium |
| 统计每个客户的设备总数 | SELECT ... | t_bz_config_customer, t_bz_config_ci_ne_root | Simple |
| ... | ... | ... | ... |

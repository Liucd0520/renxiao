## 12月25日 - SQL 生成方案设计与代码完善

### 工作背景

在完成检索阶段的优化后（24号使用3表生成300问题进行大规模测试，效果良好），开始进入 SQL 生成阶段。设计了两种方案：

### 两种 SQL 生成方案

**方案 A - 直接生成**
- 将检索得到的 10-20 张表的完整 Schema 直接传给 LLM
- LLM 自行选择所需的表并生成 SQL

**方案 B - 先筛后生**
- 先用 LLM 从 10-20 张表中筛选出 3-5 张最相关的表
- 再用筛选后的精简 Schema 生成 SQL

### 主要工作

1. **完善 `table_filter.py`** - 实现方案 B 的表筛选功能
   - 加载表级别 Schema（含列信息）
   - 使用 LLM 进行表筛选
   
2. **完善 `sql_generator.py`** - 实现 SQL 生成功能
   - 构建完整的表 Schema 文本（表名、描述、列名、列类型、列描述）
   - 调用 LLM 生成 SQL

3. **150 题批量测试**
   - 生成了 `scheme_a_150_results.json` 和 `scheme_b_150_results.json`
   - 产出了详细的 SQL Review 报告

---

## 12月26日 - 全链路测试与方案对比

### 主要工作

1. **7 题原始问题全链路测试**
   - 使用 `cc_result.csv` 中的 7 个人工校准问题
   - 完整运行检索 → 筛选(方案B) → SQL 生成流程
   - 与人工正确答案进行严格对比

2. **LLM 输入信息统计**
   
   | 指标 | 数值 |
   |-----|------|
   | 每题平均 Schema | ~9,400 tokens |
   | 占 32B 模型上下文 | ~29% |
   | 确认：只传 10 张表 | ✅（不是 344 张） |

3. **最终测试结果**

   | 方案 | 正确率 |
   |:---:|:------:|
   | **A** | **85.7%** (6/7) |
   | **B** | **28.6%** (2/7) |

4. **方案 B 失败原因分析**
   - 筛选错误：选错表或漏掉关键表（如 customer 表）
   - SQL 生成错误：漏掉过滤条件、用错字段名

### 产出文件

- `docs/milestone_20241226/original_7q_full_report.md` - 完整全链路报告
- `docs/milestone_20241226/original_7q_results_v2.json` - 测试结果数据
- `cc_result.csv` - 更新添加了方案A/B的SQL及判定结果

# 纯 LLM 直接选表方案报告

**报告日期**: 2025-12-15  
**方案状态**: 实验阶段

---

## 方案概述

**核心思路**：跳过向量检索，直接让 LLM 从 344 张表中选择相关表。

**可行性依据**：
```
344 张表 × 平均 70 字符描述 = ~25,000 字符 ≈ 6,000 tokens
```
完全在 LLM 上下文窗口内（QwQ-32B 支持 131k tokens）

---

## 方案流程

```
用户问题 + 344张表的描述列表 
     ↓
   LLM 直接选表（top 10）
     ↓
  展开所选表的所有列
     ↓
   LLM 生成 SQL
```

**对比 LinkAlign 流程**：

| 步骤 | LinkAlign | 纯 LLM 方案 |
|------|-----------|-------------|
| 表/列检索 | 向量检索 | LLM 直接选表 |
| 过滤 | LLM 按列投票 | - |
| 语言对齐 | 英文模型 | LLM 自然理解 |

---

## 实现步骤

### 1. 表级别 Schema 提取

**工具**: `extract_table_level_schema_enhanced.py`

**功能**: 
- 连接 MySQL 数据库
- 提取每张表的结构信息
- 用 LLM 为每张表生成中文描述

**执行结果**:
```
提取表数: 344 张
LLM 生成描述: 344 个
耗时: 约 41 分钟
```

### 2. LLM 直接选表

**工具**: `select_tables_with_llm.py`

**Prompt 设计**:
```
你是一个数据库专家。根据用户的问题，从以下表列表中选择最相关的表。

## 用户问题
{question}

## 可用的表
1. t_bz_config_customer: 客户配置信息表...
2. event_history: 事件历史记录表...
...（共344张表）

## 选择的表:
```

## 测试结果

**测试数据**: cc_result.csv（7 个业务问题）

| 问题 | 期望表 | 召回率 |
|------|--------|--------|
| ciscoA 告警统计 | `event_history`, `t_bz_config_ci_ne_root` | 0% |
| 设备 down 超 3 月 | 3 张表 | 0% |
| 平台有多少客户 | `t_bz_config_customer` | **100%** ✅ |
| 平台有多少设备 | `t_bz_config_ci_ne_root` | 0% |
| 上月新上线设备 | `t_bz_config_ci_ne_root` | 0% |
| 上月下线设备 | `t_bz_config_ci_ne_root` | 0% |
| 客户设备告警详情 | `event_history`, `t_bz_config_ci_ne_root` | **50%** ✅ |

**汇总**:
- 测试用例数: 7
- 平均召回率: **21.4%**
- 对比 LinkAlign 向量检索: ~14%（提升 7 个百分点）

## 结果分析

### 成功案例

**客户表 `t_bz_config_customer`**: 100% 召回
```
描述: 客户配置信息表，存储客户基础数据及关联参数
LLM 判断: ✅ 准确识别
```

### 失败案例

**设备表 `t_bz_config_ci_ne_root`**: 0% 召回

LLM 看到"设备"这个词时选择的是:
- `t_gn_all_net_device`（设备统计表）
- `uptime`（设备上下线时间）

而不是核心表 `t_bz_config_ci_ne_root`

**原因**: 表描述不够突出"设备主表"地位
```
当前描述: 设备配置信息表，存储网元设备的基础属性...
应该的描述: 【设备主表】存储所有设备的核心配置信息...
```

## 优化方向

1. **改进核心表描述**: 加入"主表"、"核心"等标识
2. **尝试更强模型**: qwen-max 或 GPT-4
3. **业务词典映射**: 显式定义"设备"→`t_bz_config_ci_ne_root`

## 结论

| 维度 | 评价 |
|------|------|
| 可行性 | ✅ 技术上可行（6k tokens 在上下文内）|
| 效果 | ⚠️ 21.4% 召回率，优于向量检索但仍不足 |
| 瓶颈 | 表描述质量决定召回效果 |
| 下一步 | 优化核心表描述 / 尝试更强模型 |

> [!NOTE]
> **纯 LLM 方案的核心价值是绕过了向量检索的中英文不匹配问题。**
> **但成功率高度依赖表描述质量，需要进一步优化。**

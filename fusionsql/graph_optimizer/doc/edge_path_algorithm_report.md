## 4. 算法对比分析

### 4.1 为什么 PPR 在真实数据上无效？

**硬编码数据 vs 真实数据**：

| 数据类型       | 候选表数           | 1-hop 扩展后       | PPR 效果               |
| -------------- | ------------------ | ------------------ | ---------------------- |
| 硬编码         | 10 张              | ~70 张             | +1~2 位（假象）        |
| **真实** | **26-28 张** | **~150+ 张** | **0 位（无效）** |

**根本原因**：真实数据候选表更多，1-hop 扩展后图更大，PPR 信号稀释更严重。

### 4.2 为什么边/路径算法有效？

| 特性     | PPR               | 边/路径                      |
| -------- | ----------------- | ---------------------------- |
| 图规模   | 150+ 表（扩展后） | **26-28 表（不扩展）** |
| 信号传递 | 全局扩散，稀释    | **局部路径，聚焦**     |
| 评分依据 | 只看结构距离      | **传递 BGE 语义分数**  |

### 4.3 关键洞察

> **2-hop 连通性只回答**："我离重要表有多远？"
>
> **边/路径算法回答**："路径上的高分表有多高？它们的语义分数能传递给我多少？"

**具体对比**：

| 算法              | event_history 的分数计算                 | 效果                            |
| ----------------- | ---------------------------------------- | ------------------------------- |
| PPR/连通性        | `1/(distance+1) = 0.5`                 | 无语义信息                      |
| **边/路径** | `avg(5.07, 2.53, 1.55) × 0.33 = 1.01` | **包含高分表的 BGE 分数** |

## 5. 边/路径算法详细设计

### 5.1 核心思想：语义光环效应

> 如果表 A 与高分表 B 有外键连接，则 A 可能也是相关表。

```
高分表 B (BGE=5.07)
    │
    FK (外键)
    │
    ▼
低分但关键的表 A (BGE=1.55)

→ A 通过路径获得 B 的"光环加成"
```

### 5.2 算法流程

```python
def optimize(candidates):
    # 1. 获取候选表之间的边（不扩展！）
    relationships = get_table_relationships(candidates)

    # 2. 找所有 2-hop 和 3-hop 路径
    paths = find_all_paths(candidates, max_length=3)

    # 3. 计算路径分数（语义传递）
    for path in paths:
        path_score = avg(bge_scores[t] for t in path) / len(path)
        for table in path:
            contributions[table] += path_score

    # 4. 加分
    final = bge + 0.4 * max_bge * normalized_contribution
```

### 5.3 关键参数

| 参数            | 值             | 说明             |
| --------------- | -------------- | ---------------- |
| boost_factor    | 0.4 × max_bge | 加成幅度         |
| max_path_length | 3              | 最长路径         |
| 路径聚合        | avg（均值）    | 考虑路径上所有表 |
| 长度衰减        | 1/len          | 越短越好         |

### 5.4 为什么用均值而非最大值？

| 聚合方式      | Q1 效果       | 分析                |
| ------------- | ------------- | ------------------- |
| max           | +8            | 只看最高分          |
| **avg** | **+12** | 考虑路径上所有表 ⭐ |
| softmax       | +8            | 平滑版 max          |

## 7. 与之前算法的对比

### 7.1 步骤 1-5 回顾

| 步骤              | 内容             | 真实数据效果           |
| ----------------- | ---------------- | ---------------------- |
| 步骤 1            | BGE 加权 PPR     | 0 位提升               |
| 步骤 2            | 2-hop 连通性     | 0 位提升               |
| 步骤 3            | 单表/多表门控    | 正确分流               |
| 步骤 4            | MOSTLYIS 稀疏化  | 减少噪声               |
| 步骤 5            | 局部子图 PPR     | 0 位提升               |
| **边/路径** | **本报告** | **17 位提升** ⭐ |

### 7.2 为什么步骤 1-5 的 PPR 没效果？

1. **1-hop 扩展导致图太大**：26 表 → 150+ 表
2. **PPR 稀释效应**：分数分散到无关表
3. **只看距离，不看语义**：1/(d+1) 没有利用 BGE 分数

### 7.3 边/路径算法的改进

1. **不扩展**：直接在 26-28 表之间计算
2. **语义传递**：路径分数 = BGE 分数的函数
3. **累加效应**：多条路径的贡献叠加

## 8. 结论

### 8.1 核心发现

1. **边/路径算法是唯一有效的图优化方法**

   - 总提升：17 位
   - 最大提升：Q1 event_history +12 位
2. **PPR 算法在真实数据上无效**

   - 总提升：0 位
   - 甚至有负面效果（Q2 -1 位）
3. **之前的测试数据不可靠**

   - 硬编码 10 表 vs 真实 26-28 表
   - PPR 的"假阳性"被真实数据揭穿

### 8.2 算法特点

| 优点             | 说明               |
| ---------------- | ------------------ |
| **高效**   | 不需要构建大图     |
| **精准**   | 不引入无关邻居表   |
| **可解释** | 加分来自明确的路径 |
| **有效**   | 真实数据验证       |

### 8.3 适用场景

- 候选表数量：10-30 张
- 外键覆盖率低（< 30%）
- JOIN 深度浅（2-3 跳）

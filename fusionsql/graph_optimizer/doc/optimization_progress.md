## 步骤 1-4: PPR 相关优化（融合测试）

> **说明**：步骤 1-4 在代码中融合实现于 `_hybrid_selection()` 方法，无法单独拆分测试。
> 以下记录的是融合后的整体效果。

### 包含的优化

| 步骤 | 优化项 | 内容 |
|------|--------|------|
| 1 | BGE 加权 PPR | PPR 播种按 BGE 分数加权（而非均匀） |
| 2 | 2-hop 连通性 | 支持间接连接，路径强度衰减 1/(d+1) |
| 3 | 单表/多表门控 | 单表场景跳过图优化 |
| 4 | MOSTLYIS 稀疏化 | 列名相似度过滤 + top-k + 动态权重 |

### 真实数据效果

| 指标 | 结果 |
|------|------|
| 总提升 | 0 位 |
| 有提升的 | 1/12 (Q7 t_bz_config_ci_ne_root: +1) |
| 有下降的 | 1/12 (Q2 event_history: -1) |

### 为什么 PPR 在真实数据上无效？

| 问题 | 原因 |
|------|------|
| **1-hop 扩展导致图太大** | 26 表 → 150+ 表 |
| **PPR 分数被稀释** | 权重分散到无关表 |
| **只看结构距离** | 没有利用 BGE 语义分数 |

**结论**：PPR 方法在外键覆盖率低、存在枢纽表的场景下效果有限。

## 步骤 5: 局部子图 PPR

### 核心思想

> 不做 1-hop 扩展，只在 top-N 候选表之间计算 PPR

```python
# 原做法（步骤1-4）
graph = self._build_subgraph(table_names)  # 扩展邻居 → 150+ 表

# 新做法（步骤5）
graph = self._build_local_subgraph(top_n_tables)  # 不扩展 → 26 表
```

### 真实数据效果

| 指标 | 结果 |
|------|------|
| 总提升 | 0 位 |
| 有提升的 | 1/12 (Q7 event_history: +1) |
| 有下降的 | 1/12 (Q2 event_history: -1) |

### 为什么局部子图 PPR 也无效？

| 问题 | 原因 |
|------|------|
| **候选表之间边太少** | top-15 之间只有 3-5 条边 |
| **PPR 传播受限** | 大部分表是孤立节点 |
| **无法形成有效传递** | 图太稀疏 |

**结论**：外键覆盖率低时，局部子图 PPR 传播不充分。

## 步骤 6: 边/路径算法 ⭐

### 核心思想

> **语义光环效应**：如果表 A 与高分表 B 有外键连接，则 A 可能也是相关表

```
高分表 B (BGE=5.07)
    │
    FK (外键)
    │
    ▼
低分但关键的表 A (BGE=1.55)

→ A 通过路径获得 B 的"光环加成"
```

### 算法流程

```python
def optimize(candidates):
    # 1. 获取候选表之间的边（不扩展！）
    relationships = get_table_relationships(candidates)

    # 2. 找所有 2-hop 和 3-hop 路径
    paths = find_all_paths(candidates, max_length=3)

    # 3. 计算路径分数（语义传递）
    for path in paths:
        path_score = avg(bge_scores[t] for t in path) / len(path)
        for table in path:
            contributions[table] += path_score

    # 4. 加分
    final = bge + 0.4 * max_bge * normalized_contribution
```

### 关键参数

| 参数 | 值 | 说明 |
|------|----|----|
| boost_factor | 0.4 × max_bge | 加成幅度 |
| max_path_length | 3 | 最长路径 |
| 路径聚合 | avg（均值） | 考虑路径上所有表 |
| 长度衰减 | 1/len | 越短越好 |

### 真实数据效果

| 指标 | 结果 |
|------|------|
| **总提升** | **17 位** ⭐ |
| **有提升的** | 3/12 |
| **有下降的** | 0/12 |
| **最大提升** | Q1 event_history: #16 → #4 (+12) |

### 与 PPR 的关键差异

| 特性 | PPR | 边/路径 |
|------|-----|---------|
| 图规模 | 150+ 表（扩展后） | **26-28 表（不扩展）** |
| 信号传递 | 全局扩散，稀释 | **局部路径，聚焦** |
| 评分依据 | 只看结构距离 | **传递 BGE 语义分数** |

### 为什么边/路径有效？

| 优点 | 说明 |
|------|------|
| **不扩展** | 避免引入无关邻居表 |
| **语义传递** | 高分表的分数沿路径传给低分表 |
| **累加效应** | 多条路径的贡献叠加 |
| **可解释** | 加分来自明确的外键路径 |

## 结论

1. **边/路径算法是唯一有效的图优化方法**
   - 总提升：17 位
   - 最大提升：Q1 event_history +12 位

2. **PPR 算法在真实数据上无效**
   - 原因：1-hop 扩展导致图太大，信号稀释

3. **推荐使用边/路径算法替代 PPR**
   - 效率更高（不扩展邻居）
   - 效果更好（语义传递）
   - 更可解释（路径可追溯）
